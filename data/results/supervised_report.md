# Supervised baseline vs Isolation Forest vs a one-line rule

Generated by `python -m src.fraud_detection.supervised --n-splits 5 --n-repeats 5 --seed 42` from the tracked `data/clean/*.csv` and `data/ground_truth_fraud_ids.csv`. Offline; deterministic. Every comparison word in the findings ('above', 'below', 'equal to') is computed from the means at 3 decimals.

## Setup

- Population: 9370 beneficiaries with >= 1 payment (features from `isolation_forest.build_features`).
- `multivariate_anomaly` (primary): 25 positives (0.27%). `any_planted` (secondary): 1005 positives (10.73%).
- 5-fold stratified CV repeated 5x (seed 42) = 25 test folds; each `multivariate_anomaly` test fold holds only ~5 positives, so one hit moves recall by ~0.20. Cells are `mean ± std [min-max]` over folds.
- A random ranking has PR-AUC ≈ prevalence (0.0027 primary, 0.1073 secondary) and ROC-AUC 0.5.
- `isolation_forest` is fit on the training fold without labels (300 trees, contamination 0.05, seed 42) and scores the test fold. The rule needs no training.
- Budget metrics flag the top 1% / 5% of each test fold; ties at the cut-off are split in expectation.

## Plain-language findings

1. **n_payments = 7 alone identifies the planted anomaly.** The 25 planted anomalies have n_payments = 7 (x25); 25 beneficiaries in total have exactly 7. The rule `n_payments > 6` flags 595 beneficiaries, catching 25/25 (precision 0.042). Of its other 570 flags, 570 are other planted frauds in the answer key (n_payments 8-12); against `any_planted` the rule has precision 1.000 and recall 0.592.
2. **All features, primary target.** PR-AUC: HGB 1.000, Isolation Forest 0.018, rule 0.042. HGB permutation importance: n_payments mean AP drop 0.902, largest other feature 0.000. Given finding 1, HGB is learning 'exactly 7 payments', which is how the generator planted the class, not a fraud insight.
3. **Where the supervised models do NOT beat the rule (primary target).** Against the rule, HGB is below in 4, above in 14 of 18 (feature set x metric) cells; logistic regression is below in 16, above in 2 of 18 (feature set x metric) cells; Isolation Forest is below in 18 of 18 (feature set x metric) cells. Logistic regression is monotone in each feature, so it cannot express a single payment count. All features: PR-AUC 0.047 vs rule 0.042 (above); at the 1% budget recall 0.008 vs rule 0.161 (below) and precision 0.002 vs rule 0.042 (below); at the 5% budget recall 0.776 vs rule 0.795 (below). Without n_payments (`no_count`): 1% recall 0.008 vs rule 0.161 (below), 5% recall 0.744 vs rule 0.795 (below). Every such cell is listed in 'Cells where a supervised model does not beat the rule' below.
4. **Dropping n_payments alone.** total_amount = mean_amount x n_payments still carries the count. HGB PR-AUC 0.813 (all features 1.000); top permutation-importance feature total_amount (AP drop 0.801).
5. **Without count and total (`no_count_no_total`).** PR-AUC: HGB 0.292 (fold range 0.01-0.61), logreg 0.045, Isolation Forest 0.019, rule 0.042, random ≈ 0.0027. HGB precision at 1% 0.086 vs rule 0.042 (above); recall at 5% 0.417 vs rule 0.795 (below), and below logreg (0.649). What is left to learn: median mean_amount 8286 for planted anomalies vs 7300 for the rest, median income 5000 vs 12000, median amount_to_income 1.66 vs 0.61. With ~5 positives per fold the spread is wide.
6. **Secondary target (`any_planted`).** PR-AUC: HGB (all) 0.689 vs rule 0.636 (above), logreg (all) 0.672 vs rule 0.636 (above), Isolation Forest (all) 0.539 vs rule 0.636 (below). At both budgets HGB (all) is equal to the rule on precision and recall (precision at 5% 1.000 vs 1.000, recall at 5% 0.468 vs 0.468). Without count/total HGB PR-AUC is 0.375. Identity fraud (duplicates, shared accounts) is not described by these per-beneficiary amount features; that is the job of the rule-based and fuzzy detectors.

Bottom line: a supervised score here is a ceiling for these features on synthetic labels, not evidence that a supervised model would work on real cases, where labels are scarce and fraud patterns move. On the primary target HGB PR-AUC is 1.000 with all features and 0.292 once the payment count and total are removed.

## Leakage guard

Features are built by `isolation_forest.build_features` before the answer key is read; labels are attached afterwards as `y_*` columns. `assert_no_leakage` runs on every feature set inside `run_cv` and rejects answer-key columns, `y_*` labels, identifiers (`row_id`, `beneficiary_id`) and anything outside `FEATURE_COLUMNS`. Pinned by `tests/test_supervised.py`.

## Caveats

- 25 positives: fold-level numbers move in steps of ~0.20 recall; trust the spread, not the third decimal.
- Isolation Forest here is fit per training fold (~7496 rows), not on the whole scored population as `isolation_forest.fit_and_score` does, so its numbers are not the project's Isolation Forest run.
- The CSV has no DB `row_id`; file order stands in for it (only used to pick one row per duplicated beneficiary_id). Results can differ slightly from the DB-backed Isolation Forest run.
- `any_planted` labels only beneficiaries named in the answer key; hub-account owners are not listed there and count as negatives.
